# hyprmoncfg panel 2.16.0

Give every display workspaces of its own, the way Omarchy 4.5 does, and choose how many. Requires hyprmoncfg 1.24.0 or newer; Per display needs hyprmoncfg 1.30.0.

Install or update through Omarchy's plugin manager: [hyprmoncfg panel](https://github.com/crmne/omarchy-hyprmoncfg).

## New

- **Per display workspaces.** The Workspaces strategy list offers Per display when the daemon supports it, hyprmoncfg [1.30.0](https://github.com/crmne/hyprmoncfg/releases/tag/v1.30.0) or newer. Each display gets its own workspaces, numbered from 1, and `Super + number` goes to that workspace on the display you're on. On Omarchy 4.5 and later, Omarchy keeps running them, and the panel shows which block Omarchy gives each display.
- **Choose how many workspaces each display has**, from 1 to 10, with a stepper in place of Max workspaces.
- **Workspaces read 1-10 on every display.** The plan and the display map show the second display's workspace 11 as 1, as Omarchy's bar does. The plan adds Hyprland's own numbers in parentheses, since window rules still use them.
- **A label for another unit of a saved monitor model.** A profile that applies because a different unit of the same monitor is plugged in says so in its match details. The text is English for now in every language.

## Fixed

- **Bordered boxes keep all four sides with square corners.** On screens with fractional scaling, such as 1.33 or 1.6, the edge of the scrolling area cut off the left or right border of boxes flush against it, like "Managed by hyprmoncfg".

## What's tested

288 Node tests pass, along with the QML suites, including a new test that the scrolling area clips past its edges without moving its contents. The clipped border was reproduced in an offscreen render at 1.25, 1.33 and 1.6 scale and is gone with the fix. Per display and the plan labels were tried live on Omarchy 4.5 with the hyprmoncfg 1.30.0 daemon. The count stepper and the display map labels were not captured.
