# hyprmoncfg panel 2.4.0: Your displays, clearly

A cleaner everyday panel, a more focused full editor, and fewer surprises when displays connect. Built to accompany [hyprmoncfg 1.19.0](https://github.com/crmne/hyprmoncfg/releases/tag/v1.19.0).

![Compact display panel](https://raw.githubusercontent.com/crmne/omarchy-hyprmoncfg/v2.4.0/preview.png)

## Less clutter, clearer actions

- The expanded editor follows **1 Layout, 2 Workspaces, 3 Profiles**, matching the TUI. The old 2/3 shortcuts have swapped.
- Identify all, Keys, TUI, and Compact share a compact header. Setup status and Create profile live together in a footer shared with the compact panel, without a second TUI card or repeated status line.
- Display cards and Identify use connector, model with whole-inch size, resolution@Hz, scale, position, and workspace IDs. Formatting stays compact: `3840x2160@144Hz`, `1.5x`, `32"`.
- Hardware information shows all six fields directly. Identify is a visible button; no More details toggle is needed. Live brightness stays in the compact panel, separate from profile settings.
- Position controls use horizontal minus/value/plus steppers. Off and mirrored displays remain visible and selectable.

![Expanded layout editor](https://raw.githubusercontent.com/crmne/omarchy-hyprmoncfg/v2.4.0/screenshots/layout.png)

## Profiles that are easier to understand

- Discoverable profile menus open beside their source row through right-click, the menu button, or the keyboard. Delete uses a themed confirmation.
- Profile headings and values line up, with no redundant selection arrow. **Post-apply command** is consistently named, editable, and last in the details.
- Preview a saved profile without first turning automatic selection off. The default confirmation window is now **30 seconds**.
- A successful backend-confirmed save establishes the clean editor state, so completed work no longer keeps offering Preview & save.
- The permanent marketplace-review prompt is gone. Genuine installation, compatibility, and daemon-restart actions remain available.

![Saved profiles](https://raw.githubusercontent.com/crmne/omarchy-hyprmoncfg/v2.4.0/screenshots/profiles.png)

## Reliable refreshes and workspace planning

Background status and editor refreshes preserve draft edits and active input. Delayed replies cannot overwrite newer topology or preview state, and a busy compositor keeps the last visible snapshot while reads retry.

Identify uses a fresh live snapshot, remains input-transparent, and cancels outdated cues on topology changes or preview activity. It does not apply a layout or cover an active TUI preview.

The workspace editor exposes **First per display** and **All assigned** persistence. The companion backend prefers Sequential for new plans and ambiguous single-display imports while preserving explicit saved workspace intent.

![Workspace planner](https://raw.githubusercontent.com/crmne/omarchy-hyprmoncfg/v2.4.0/screenshots/workspaces.png)

## Upgrade

Requires **hyprmoncfg 1.19.0 or newer**. Upgrade the backend, restart its user service, then update the plugin:

```sh
systemctl --user restart hyprmoncfgd.service
omarchy plugin update crmne.hyprmoncfg
```

If an already-open shell retains old QML, close the panel and run `omarchy restart shell`.

Screenshots show the actual panel QML with synthetic profiles/displays in an isolated capture host. They are not hardware acceptance tests. Panel/TUI terminology and core workflows are aligned, but standalone TUI Identify and its profile context menu remain pending. Layout reuse, shared preferences, and notification routing are not included. See the [backend notes](https://github.com/crmne/hyprmoncfg/releases/tag/v1.19.0) for remaining physical recovery limits.
